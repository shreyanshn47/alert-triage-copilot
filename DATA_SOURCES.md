# Data sources and licenses

No confidential, employer or client data is used anywhere in this repository. Everything
below is public, or generated by a script in this repo.

| Source | What it is used for | License | Committed to the repo? |
|---|---|---|---|
| [OTRF Security-Datasets](https://github.com/OTRF/Security-Datasets) | Malicious alerts for T1003.001, T1021.002, T1110 (and T1547.001) | MIT, Copyright (c) 2021 Open Threat Research Forge | A 52-row slice, in `data/labeled/malicious.jsonl` (see below) |
| [Splunk attack_data](https://github.com/splunk/attack_data) | Malicious alerts for T1059.001, T1053.005, T1547.001, T1003.001 | Apache License 2.0 | Same slice |
| [MITRE ATT&CK](https://attack.mitre.org) v20.0 (STIX) | Retrieval corpus | See notice below | No: `data/fetch_attack.py` downloads it |
| [SigmaHQ rules](https://github.com/SigmaHQ/sigma) at the commit in `data/sigma_commit.txt` | Retrieval corpus | Detection Rule License (DRL) 1.1 | No: `data/fetch_sigma.py` downloads it |
| `data/make_benign.py` | 60 synthetic benign look-alike alerts | Ours (generated, fixed seed) | Yes, `data/labeled/benign.jsonl` |
| `data/make_injection.py` | 20 synthetic prompt-injection samples, each a malicious alert plus an attacker's payload | Ours (generated) | Yes, `data/labeled/injection.jsonl` |

Raw downloads go to `data/raw/` (git-ignored). Each download is pinned: SHA-256 values in
`data/*_checksums.json`, and the Sigma commit in `data/sigma_commit.txt`. A mismatch stops the script.

## How the labeled set is built, and what that means

* **The label is the technique the dataset is filed under**, not a judgement about each event.
  Those captures also contain background activity, so `data/build_labeled.py` keeps only events
  chosen by a per-technique selector (event type plus the tool or object involved).
* **Some "malicious" events look harmless on their own.** For example a PowerShell inventory
  command inside a dataset filed under T1059.001. A model that calls that benign is not
  necessarily wrong. Read recall numbers with this in mind.
* Events are kept only if their fingerprint is new, then sampled round-robin across source files
  with a fixed seed. Dev and test hold different fingerprints, but events from the same capture
  can land on both sides, so the two sets are not fully independent.
* The sets are small: 52 malicious (not the 60 planned: OTRF has only 5 distinct SMB events and
  7 failed-logon events) plus 60 benign. 18 malicious and 18 benign are dev, 34 and 42 are test.
* Public datasets and Sigma rules may have been seen by the language model during training, and
  Sigma rules were written to detect the same behaviours the datasets contain. Both flatter
  retrieval and LLM results.
